# Skill Taxonomy Human Review Checklist — CF-03.2B

Use one checklist per Skill candidate. All entries begin unresolved. A reviewer
must cite the source item, rubric, or decision record supporting any resolution.

## Identity and hierarchy

- [ ] Candidate ID is preserved exactly and unique across TSA/HSA.
- [ ] Exam and question-bearing Section are correct.
- [ ] Competency, Domain, and Topic form a valid parent path in the reviewed
  taxonomy version.
- [ ] A blank Topic is explicitly unresolved; no proposed label is represented
  as an existing canonical ID.
- [ ] HSA Part 3 is assigned to `HSA_SCIENCE` or `HSA_ENGLISH`, never
  `HSA_OPTIONAL`.
- [ ] `subject_choice` is set from item evidence for HSA Science when applicable.

## Construct definition

- [ ] Operational definition describes one learner capability rather than a
  topic label, content list, question format, or general test-taking quality.
- [ ] Observable action can be expressed as what a learner does in a response.
- [ ] In-scope content has a clear positive boundary.
- [ ] Out-of-scope content has explicit negative boundary examples.
- [ ] Definition does not embed M1–M3, item difficulty, or English proficiency
  as part of the Skill.
- [ ] For English, A2–C1 proficiency remains a separate construct.

## Assessment evidence

- [ ] At least one representative item elicits the proposed action.
- [ ] The expected response evidence is identified (selection, calculation,
  explanation, comparison, inference, etc.) without relying only on stimulus
  type or answer format.
- [ ] A scoring key/rubric identifies evidence of the action and common
  non-evidence.
- [ ] The item provides enough information to attribute the response to this
  Skill rather than an unmodelled prerequisite.
- [ ] Grouped/passage-based context and sub-question evidence are retained.
- [ ] Visual/table/map/source context is available to reviewers where required.
- [ ] No reliability, validity, difficulty, or predictive claim is made without
  empirical data.

## Distinction and overlap

- [ ] Nearest sibling Skills are named and compared using positive and negative
  response examples.
- [ ] Distinction is based on the scored cognitive operation/response evidence,
  not merely different wording or item format.
- [ ] If one item supports multiple constructs, the primary-path rule and any
  secondary-tag policy are explicit.
- [ ] Candidate is not a duplicate or a narrower/wider restatement without a
  scoring rationale.
- [ ] Skill is not only a difficulty band, cognitive-level label, proficiency
  level, text type, subject label, or stimulus format.

## TSA-specific review

- [ ] TSA Math candidates under missing Domains have an approved parent
  structure before Topic IDs are assigned.
- [ ] Number, Function, Geometry, Combinatorics, Probability, and Statistics
  Topic proposals have reviewed boundaries.
- [ ] Trigonometric-equation candidate remains ambiguous until the primary
  content parent is decided.
- [ ] TSA Reading Text Type candidates are reviewed as possible stimulus tags,
  not automatically accepted as Skills.
- [ ] Statement completion is distinguished from response format and direct
  information retrieval.
- [ ] TSA Science content Topics are neither too broad to score nor so narrow
  that they duplicate item-specific facts.

## HSA-specific review

- [ ] HSA Science and English remain mutually exclusive optional branches.
- [ ] Science subject-specific content is not conflated with cross-subject
  evidence/data/reasoning operations.
- [ ] A policy resolves primary path for questions that require both subject
  knowledge and data/reasoning.
- [ ] HSA English Skills are reviewed against representative English items and
  separately calibrated to proficiency levels where applicable.
- [ ] No equivalence between A2–C1, M1–M3, and difficulty levels is assumed.

## Decision record

- [ ] Outcome is recorded as retain, revise, split, merge, re-parent, or reject.
- [ ] Rationale, reviewer role/name, date, and evidence references are recorded
  in the authorized review process.
- [ ] Any approved change is made only in a separately versioned proposal after
  this review; the source framework remains unchanged until the approval gate.
- [ ] Database changes are blocked until taxonomy versioning and approval
  semantics are approved.
